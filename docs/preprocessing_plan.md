## 4. Memory Management and Transactional Raw-File RemovalExecuting this conversion inside a ~147 GB post-download free-space envelope requires deterministic control over both C/C++ heap memory allocation and filesystem deletion atomicity.

### 4.1 Host RAM Bounds and C-Heap Leak PreventionLong-running Python imaging jobs commonly exhaust system memory because C++ libraries (ITK/GDCM inside SimpleITK, zlib gzip decompression, and libhdf5) retain fragmented heap arenas across thousands of volumes, while nibabel caches full float64 arrays on image objects by default. Enforce five memory-isolation rules across all ingestion workers:Recycle Worker Subprocesses Per Patient (max_tasks_per_child=1): Dispatch each patient ID to a concurrent.futures.ProcessPoolExecutor(max_workers=4, max_tasks_per_child=1). When the subprocess finishes preparing that single patient's longitudinal arrays, the process exits and the Linux kernel immediately reclaims 100% of SimpleITK, pydicom, and zlib C-heap allocations.Isolate HDF5 Writes Behind a Bounded Queue (maxsize=2): Because standard non-MPI h5py requires single-writer serialization, workers pass prepared NumPy buffers over a bounded queue (maxsize=2) to one dedicated HDF5 Shard Writer process. Capping queue depth at two patients prevents fast readers from piling up uncompressed 3D volumes in RAM if disk flushing slows.Bypass nibabel's Internal float64 Cache: Never call img.get_fdata() with default settings, which upcasts voxels to float64 and pins the array inside img._fdata_cache (caching='fill') until garbage collection. Always invoke img.get_fdata(dtype=np.float32, caching='unchanged') (or slice img.dataobj directly after checking img.header.get_slope_inter()), then explicitly call img.uncache() and delete the proxy reference.Stream DICOM Series Sequentially with In-Place float32 Scaling: After Pass 1 (stop_before_pixels=True or SimpleITK.ImageFileReader.ReadImageInformation()), Pass 2 loads pixel data for one 3D series/phase at a time, pre-allocates a single np.empty((Z, Y, X), dtype=np.float32) buffer, applies RescaleSlope and RescaleIntercept in-place (np.multiply(..., out=buf); np.add(..., out=buf)), and releases the buffer before reading the next series.Ban Variable-Length HDF5 Strings: Assert in the writer wrapper that every attribute and compound column uses numeric dtypes or fixed-length np.bytes_ (|S...), routing all variable-length text/JSON into uint8 orjson byte arrays to eliminate H5Treclaim heap growth.
